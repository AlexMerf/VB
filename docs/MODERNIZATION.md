# VB — план модернизации («второе дыхание»)

Статус: **в работе**. Ветка `modern`. Наследие заморожено в теге `v1.0-legacy` и ветке `legacy`.

## Зачем

Сайт-портфолио Валерии Белобородовой (VB) живёт с 2023 года на Next.js 13.2.4 и фактически не работает как бизнес-инструмент:

- форма брифа не отправляет заявки (в клиенте читается `process.env.TELEGRAM_TOKEN`, который Next не инлайнит без `NEXT_PUBLIC_`; в Vercel у проекта вообще нет переменных окружения);
- production-домен `vb-olive.vercel.app` не открывается с российских сетей (DNS резолвится, TCP-таймаут; `vercel.com` при этом отвечает) — целевая аудитория сайта физически не может его увидеть;
- дизайн сильный, но техническая база устарела на три мажорных поколения: нет SEO, OG, 404, политики конфиденциальности, тестов и CI.

Цель — сохранить дизайн и контент, заменив фундамент и процессы.

## Зафиксированные решения (2026-10-21)

| Вопрос | Решение |
| --- | --- |
| Глубина миграции | Максимум: Next 16 App Router + React 19 + TypeScript strict, MUI выпиливаем |
| Дизайн | 1:1, но разрешены аккуратные освежения там, где явно устарело (отдельные коммиты + скриншот-дифф) |
| Контент | Код + типизированный JSON (Zod-схема), без CMS |
| Хостинг | Vercel, как сейчас; production-деплой — только с подтверждением владельца |

## Целевой стек

По состоянию на 2026-10: `next@16.4.2`, `react@19.3.1` / `react-dom`, `typescript@7.0.2` (fallback на 5.x при несовместимости), `motion@14.4.0`, `sass@1.105.2`, `zod`, `@playwright/test`, ESLint 9 (flat config) + Prettier.

Node: 22.x локально и на Vercel (у проекта сейчас выставлен 18.x — обновить).

Что остаётся: SCSS-модули, CSS-переменные и миксины, все тексты, изображения, структура секций, брейкпоинты.

Что меняется:

- Pages Router → App Router, серверные компоненты для статики, клиентские — только для интерактива;
- `@import` в SCSS → `@use`/`@forward`;
- Google Fonts через CSS `@import` → `next/font` (self-hosted, без внешнего запроса);
- MUI 5 + emotion → собственные примитивы (TextField с плавающим лейблом, Radio, Drawer, Tooltip, иконки inline SVG);
- `axios` + клиентский Telegram → Server Action, токен только на сервере;
- JSON без типов → Zod-схемы + единый источник данных о проектах (сейчас карточки портфолио захардкожены в `portfolio.tsx` и дублируются в JSON кейсов);
- `next lint` без конфига → ESLint 9 + Prettier;
- ноль тестов → Playwright (визуальная регрессия + e2e), Lighthouse CI, GitHub Actions, превью-деплои.

## Baseline

Собран локально из тега `v1.0-legacy` (`npm ci && next build` на Node 22 — сборка проходит, 7 статических страниц). Скриншоты: `.baseline/legacy/` (не в git), скрипт `.tools/capture.mjs`, метаданные `.baseline/legacy/meta.json`.

Почему не full-page: анимации `whileInView` с `once:false` сбрасывают блоки вне вьюпорта в начальное (невидимое) состояние. Поэтому снимаем по секциям: `top`, каждая `<section>`, `footer`, плюс `menu-open` и `form-filled` для мобильного меню и брифа. Вьюпорты: 1440×900 и 390×844.

Результат: 51 скриншот, 10,9 МБ, 10 комбинаций «страница × вьюпорт», высоты страниц зафиксированы в `meta.json`. В консоли пойманы ровно две ожидаемые ошибки: 404 на отсутствующий `/favicon.ico` и 404/400 на отсутствующий `/image/heroProject2/1.1.png`.

Правило приёмки: сравниваем те же секции в тех же вьюпортах; расхождения только из согласованного списка «освежений».

### Производительность (2026-10-21)

Замеры Lighthouse на локальном прод-билде (mobile — троттлинг по умолчанию,
desktop — preset):

| Метрика | До | После |
| --- | --- | --- |
| Mobile performance | 48 | **78–82** |
| Desktop performance | 82 | **98** |
| Mobile LCP | 18.5 s | **4.4–4.9 s** |
| Desktop LCP | 3.3 s | **0.9 s** |
| Mobile TBT | 1790 ms | **30 ms** |
| Вес страницы (mobile) | 3.1 MB | **~700 KB** |

Что сделано:

- hero-графика: исходники 1920×5300–7300 px пересжаты до 730 px по ширине
  (2× от отображаемых 365), 2.5 MB → **329 KB**; оригиналы — в теге `v1.0-legacy`;
- hero и картинки кейсов переведены на responsive `next/image` (`sizes`,
  `quality=75`) вместо `unoptimized`/`quality=100`;
- портфолио и обложки кейсов получили корректные `sizes` — браузер больше не
  тянет кандидатов 1920–3840 px;
- `PageTransition` переведён с framer-motion на CSS-анимацию: контент виден
  с первого кадра, гидрация больше не задерживает LCP;
- шрифты: убран неиспользуемый вес Mulish 700;
- бюджеты Lighthouse обновлены под фактические показатели
  (performance — warn 0.75, accessibility/SEO — error 0.95).

Остаточное ограничение: мобильный LCP упирается в 117 KB latin-подсет
Unbounded, которую next/font не прелоадит; лечится только local-фонтом или
сменой дисплейного шрифта — это уже вопрос дизайна, не техники.

## Риски

| Риск | Снижение |
| --- | --- |
| Визуальные расхождения при замене MUI | скриншот-дифф по секциям; план Б — остаться на MUI 9 |
| Несовместимость TS 7 с типами Next | fallback на TS 5.x без изменения результата |
| Sass 1.105 ломает `@import` | перевод на `@use`/`@forward` — синтаксис, не дизайн |
| `*.vercel.app` блокируется в РФ | обсудить кастомный домен/другой хостинг отдельно; в текущем скоупе — оставляем Vercel |
| Потеря истории/кода | тег и ветка `legacy`, baseline-скриншоты, `main` не перезаписывается до приёмки |
| Токен уже утёк | перевыпуск, новый токен только в env, никогда в git |

## Не делаем (non-goals)

- Не переписываем тексты и кейсы без отдельного запроса.
- Не меняем композицию и брендинг.
- Не добавляем CMS.
- Не меняем хостинг и домен в рамках этой работы.
- Не трогаем `origin/main` до приёмки.
